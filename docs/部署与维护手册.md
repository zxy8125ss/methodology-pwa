# 部署与维护手册

本文档覆盖：首次部署、日常维护、故障排查、数据备份与恢复。

## 一、架构总览

```text
iPhone / Mac / 电脑浏览器
          │
          ▼
   GitHub Pages（静态站点，本仓库 dist/）
          │
          ▼
   Cloudflare Worker（安全代理层）
      │           │
      ▼           ▼
 AI 模型接口   GitHub API
      │           │
      ▼           ▼
 Claude/      私有数据仓
 DeepSeek     zxy8125ss/methodology-data
                 │
                 ▼
          GitHub Actions（每周研究 / 校验 / 备份）
```

**为什么必须有 Worker 这一层：**

1. GitHub Pages 只能托管静态文件，无法安全保存 API Key
2. 私有数据仓需要 PAT 才能读取，若 PAT 放进前端代码即等于公开泄露
3. Worker 提供鉴权、限流、成本上限，是唯一能同时满足「前端无密钥」和「数据私有」的位置

## 二、首次部署

### 2.1 前置条件

- GitHub 账号（本项目为 `zxy8125ss`）
- Cloudflare 账号（免费额度足够个人使用）
- 至少一个 AI 服务的 API Key（推荐 Claude + DeepSeek 双配置）
- 本地 Node.js 22+

### 2.2 准备数据仓

数据仓已创建：`zxy8125ss/methodology-data`（private）。

```bash
export GH_TOKEN=$(grep -o 'gho_[A-Za-z0-9]*' ~/.config/gh/hosts.yml | head -1)

cd /path/to/methodology-data
npm run data:seed      # 写入八大领域 + 8 个经典方法论
npm run data:index     # 构建检索索引
npm run data:validate  # 校验
```

> 数据仓需要 `contents: write` 权限的 PAT。GitHub Actions 中请配置名为 `DATA_REPO_TOKEN` 的 secret。

### 2.3 部署 Worker

```bash
cd methodology-pwa
npm install

# 设置密钥（每个单独执行，交互式输入，值不会进入 shell history）
npx wrangler secret put GITHUB_TOKEN      # 数据仓 PAT（contents:write）
npx wrangler secret put APP_TOKEN        # 自定义访问令牌，建议用密码管理器生成
npx wrangler secret put ANTHROPIC_API_KEY # Claude
npx wrangler secret put DEEPSEEK_API_KEY  # DeepSeek（可选但推荐）
npx wrangler secret put TAVILY_API_KEY    # 可选，联网搜索增强
npx wrangler secret put BRAVE_API_KEY     # 可选，联网搜索增强

# 部署
npm run worker:deploy
```

部署成功后会输出访问地址，形如 `https://methodology-worker.<subdomain>.workers.dev`。

**必须立即验证**：

```bash
curl https://methodology-worker.<subdomain>.workers.dev/api/health
```

预期返回（不含密钥）：

```json
{
  "ok": true,
  "model": "claude-sonnet-4-5",
  "searchProvider": "crossref+arxiv+wikipedia+duckduckgo",
  "dataRepo": "zxy8125ss/methodology-data",
  "cost": { "inputTokens": 0, "outputTokens": 0, "estimatedCostUsd": 0 }
}
```

> `dataRepo` 为 `null` 说明 `GITHUB_TOKEN` 未配置成功，需要重新 `wrangler secret put`。

### 2.4 配置站点并部署 Pages

在仓库 `Settings → Secrets and variables → Actions` 中：

| 类型 | 名称 | 值 |
|---|---|---|
| Variable | `VITE_API_BASE` | `https://methodology-worker.<subdomain>.workers.dev` |
| Variable | `GITHUB_OWNER` | `zxy8125ss` |
| Variable | `GITHUB_REPO` | `methodology-data` |
| Secret | `DATA_REPO_TOKEN` | 数据仓 PAT（contents:write） |
| Secret | `ANTHROPIC_API_KEY` | Claude API Key |
| Secret | `DEEPSEEK_API_KEY` | DeepSeek API Key（可选） |
| Secret | `TAVILY_API_KEY` | Tavily API Key（可选） |
| Secret | `BRAVE_API_KEY` | Brave API Key（可选） |

然后启用 Pages：

`Settings → Pages → Source → GitHub Actions`

推送代码即触发自动部署：

```bash
git add -A
git commit -m "feat: 方法论 PWA 首版"
git push origin main
```

访问 `https://zxy8125ss.github.io/methodology-pwa/` 验证。

> **注意**：本项目使用 `base: './'`（相对路径），站点挂在仓库子路径下也能正常工作。若改为自定义域名无需调整。

### 2.5 首次使用

1. 打开站点 →「设置」页 → 粘贴 Worker 的 `APP_TOKEN` → 保存
2. 「设置」页确认「后端连接」显示正常
3. 「研究」页 → 填写研究目标 → 提交研究 → 等待审核队列出现候选 → 审核入库
4. 「方法论」页确认新条目已入库

## 三、日常维护

### 3.1 更新前端

```bash
git pull
npm install
npm run typecheck && npm run build
git push origin main   # Actions 自动部署
```

### 3.2 更新 Worker

```bash
npm install
npm run typecheck
npm run worker:deploy
```

### 3.5 手动触发每周研究

`Actions → Weekly Research → Run workflow`

可填 `target` 指定研究主题，留空则自动选题。

### 3.6 轮换密钥

```bash
npx wrangler secret put ANTHROPIC_API_KEY
npx wrangler secret put APP_TOKEN
```

Worker 会立即生效，无需重新部署。**旧密钥需在服务商后台撤销。**

## 四、故障排查

### 4.1 站点显示「无法连接后端」

按顺序检查：

1. Worker 是否存活：`curl <worker-url>/api/health`
2. 令牌是否正确：前端「设置」页重新粘贴 `APP_TOKEN`
3. CORS：浏览器控制台查看是否有跨域错误
4. Pages 的 `VITE_API_BASE` 变量是否配置（配置后需重新推送触发构建）

### 4.2 AI 请求返回 401

- `APP_TOKEN` 不匹配。前端保存的令牌与 Worker secret 必须完全一致
- 注意不要在令牌前后带空格

### 4.3 AI 请求返回 503

`GITHUB_TOKEN` 未配置或权限不足。重新 `wrangler secret put GITHUB_TOKEN`，并确认 PAT 有 `contents:write`。

### 4.4 研究任务失败

查看 Actions 日志。常见原因：

| 现象 | 原因 | 处理 |
|---|---|---|
| `缺少 DATA_REPO_TOKEN` | secret 未配置 | 在仓库 Secrets 中添加 |
| `缺少 AI 密钥` | AI secret 未配置 | 添加 `ANTHROPIC_API_KEY` 或 `DEEPSEEK_API_KEY` |
| `所有模型调用失败` | 密钥无效或额度耗尽 | 在服务商后台确认 |
| `已达到费用上限` | 预算用尽 | 调整 `data/config.json` 的 `costLimitPerWeek` |

### 4.5 数据冲突

Worker 使用基于 sha 的乐观并发，冲突时自动重读重试（最多 4 次）。

若持续冲突：

```bash
# 查看数据仓最近提交
cd methodology-data && git log --oneline -10

# 手动解决冲突后推送
git pull --rebase && git push
```

### 4.6 构建失败

```bash
npm run typecheck   # 先定位类型错误
npm run build       # 再看打包错误
```

Pages 部署失败时查看 Actions 日志中 `build` job 的输出。

## 五、备份与恢复

### 5.1 自动备份

`backup.yml` 每月 1 日执行，把全量数据打包写入数据仓 `backups/` 目录，同时上传 90 天保留的 artifact。

### 5.2 手动备份

```bash
export GITHUB_TOKEN_DATA=<PAT>
npm run backup
```

产物：`backups/backup-<timestamp>.json`，含全部方法论、关系、来源、案例、实践与学习数据。

### 5.3 恢复

```bash
export GITHUB_TOKEN_DATA=<PAT>

# 方式一：通过应用导入（推荐）
# 在「设置」页 → 导入 JSON → 选择备份文件

# 方式二：命令行恢复
npx tsx scripts/restore.ts backups/backup-2026-11-08T12-00-00-00.json
```

恢复前建议先做一次当前状态备份，避免误覆盖。

## 六、成本控制

| 项目 | 默认值 | 配置位置 |
|---|---|---|
| 单次任务费用上限 | $1.00 | `data/config.json` → `costLimitPerTask` |
| 每周费用上限 | $10.00 | `data/config.json` → `costLimitPerWeek` |
| 每周研究条数 | 5 | `data/config.json` → `weeklyTargetCount` |

超限时 API 返回 429 并明确提示。Worker 内存中实时累计当周消耗，`/api/health` 可查。

**降低成本的建议**：

- 日常问答走 DeepSeek（约为 Claude 的 1/10 价格）
- 深度研究才用 Claude
- 保持 `webSearchEnabled` 开启但优先用免费的 Crossref/arXiv

## 七、安全清单

上线前逐项确认：

- [ ] `APP_TOKEN` 已设置且为强随机值
- [ ] `GITHUB_TOKEN` 是最小权限 PAT（仅目标仓库 `contents:write`）
- [ ] `grep -r "sk-\|gho_\|APP_TOKEN=" src/ worker/ shared/` 无结果（密钥未进代码）
- [ ] 站点仓库不含任何个人知识数据（数据在私有仓）
- [ ] 数据仓为 private
- [ ] Cloudflare Worker 的环境变量页面无明文密钥（secret 不显示明文）
- [ ] Pages 的 Variables 中 `VITE_API_BASE` 指向 HTTPS 地址
